# Деплой АУФ Match

Цель: коллеги открывают приложение по ссылке в браузере, логинятся, работают с
общей базой. База (Neon) облачная — данные общие автоматически.

Приложение собирается из `Dockerfile` и работает на любом сервере с Docker.
Ничего специфичного для конкретного хостинга в репозитории нет.

---

## 1. Что нужно на сервере

- Docker (и `docker compose`, если разворачиваете через compose);
- открытый порт наружу и домен с HTTPS — обычно через nginx или Caddy перед
  контейнером. Приложение слушает HTTP, TLS терминируется на прокси;
- каталог на диске для загруженных файлов (см. пункт 4).

## 2. Сборка образа

```bash
git clone <адрес-репозитория> auf-match && cd auf-match
docker build -t auf-match .
```

Первая сборка долгая — 5–10 минут: внутрь ставится Chromium для скрейпинга
портфолио. Это нормально и повторяется только при смене версии Playwright.

> Строка подключения к БД нужна уже на сборке: `next build` исполняет серверный
> код страниц, а тот поднимает Prisma. В `Dockerfile` для этого задан подставной
> `ARG DATABASE_URL` — заведомо нерабочий адрес, по которому ничего не
> запрашивается. Настоящий адрес передаётся при запуске.

## 3. Переменные окружения

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | строка подключения Neon |
| `GEMINI_API_KEY` | ключ Gemini (весь AI идёт через него) |
| `BASIC_AUTH_USER` | логин для коллег, например `auf` |
| `BASIC_AUTH_PASS` | пароль (`openssl rand -base64 24`) |
| `INGEST_TOKEN` | токен внешнего приёма кандидатов (`openssl rand -base64 24`) |
| `NODE_ENV` | `production` |
| `UPLOAD_DIR` | `/app/uploads` |
| `PORT` | порт внутри контейнера, по умолчанию `3000` |
| `FIGMA_ACCESS_TOKEN` | опционально, если нужен скрейп Figma |

> ⚠️ В production `BASIC_AUTH_USER` и `BASIC_AUTH_PASS` **обязательны** — без них
> приложение отдаёт 503. Это защита от публичного доступа, а не удобство.

Держите значения в файле `.env` рядом с compose-файлом (в репозиторий он не
попадает) или в секретах вашего хостинга. В аргументах `docker run` их лучше не
писать: они видны в `ps` и остаются в истории шелла.

## 4. Постоянный том для загрузок

Резюме и аудиозаписи пишутся в `UPLOAD_DIR`. **Без примонтированного тома они
исчезнут при первом же перезапуске контейнера**, а записи в базе останутся и
будут ссылаться на пропавшие файлы.

Каталог на хосте монтируется в `/app/uploads`.

## 5. Запуск

Через compose — `docker-compose.yml`:

```yaml
services:
  app:
    image: auf-match
    restart: unless-stopped
    env_file: .env
    ports:
      - "127.0.0.1:3000:3000"
    volumes:
      - ./uploads:/app/uploads
```

```bash
docker compose up -d
```

Порт открыт только на localhost — наружу приложение отдаёт прокси, он же держит
сертификат.

Миграции применяются автоматически на старте: команда контейнера —
`prisma migrate deploy && npm run start`.

## 6. Ссылка для коллег

Направьте домен на прокси, а прокси на `127.0.0.1:3000`. Коллегам нужны
**ссылка + `BASIC_AUTH_USER` / `BASIC_AUTH_PASS`**.

## 7. Биллинг Gemini (обязательно для реальной работы)

На бесплатном тарифе лимит ~20 запросов/сутки на модель — анализ 2000+ кандидатов
упрётся в квоту в первый же час (ошибка `quota_daily`).

1. Откройте [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
2. Найдите ключ → включите биллинг на привязанном проекте Google Cloud.
3. Проект перейдёт на pay-as-you-go, лимиты вырастут до тысяч запросов в минуту.
   `gemini-2.5-flash` дешёвый — полный прогон базы стоит единицы долларов.

## 8. Доступ для внешней интеграции

Кандидатов можно заливать из стороннего продукта через API — без доступа к базе
и без общего пароля приложения.

**Эндпоинт:** `POST https://<домен>/api/candidates/ingest`
**Заголовки:** `X-Ingest-Token: <INGEST_TOKEN>`, `Content-Type: application/json`

```json
{
  "source": "Название продукта",
  "candidates": [
    { "name": "Имя Фамилия", "portfolioUrl": "https://behance.net/...", "email": "...", "telegram": "@...", "location": "..." }
  ]
}
```

Обязательны `name` и хотя бы одна ссылка (`portfolioUrl` / `url` / массив
`portfolioLinks`). До 1000 за запрос. Ответ:
`{ received, imported, skippedExisting, skippedInvalid }`. Дедуп по ссылке —
повторные заливки не задваивают людей. Кандидаты попадают со статусом `NEW` и
уходят в AI-анализ автоматически.

Отзыв доступа — сменить `INGEST_TOKEN` и перезапустить контейнер.

## Обновление приложения

```bash
git pull
docker build -t auf-match .
docker compose up -d
```

Откат — собрать образ из предыдущего коммита. Если нужны быстрые откаты, тегируйте
образы хешем коммита (`docker build -t auf-match:$(git rev-parse --short HEAD) .`)
и держите несколько последних.

## Если что-то не так

- **Сборка падает на `next build` с ошибкой Prisma** — потерялся
  `ARG DATABASE_URL` в `Dockerfile`.
- **Сборка падает на Chromium** — не хватило памяти или диска на сборочной машине.
- **503 на всех страницах** — не заданы `BASIC_AUTH_USER` / `BASIC_AUTH_PASS`.
- **Не подключается к БД** — проверьте `DATABASE_URL` и что проект Neon активен.
  Диагностика: `GET /api/health` показывает применённые настройки пула.
- **Резюме пропадают после перезапуска** — не примонтирован том на `/app/uploads`.
