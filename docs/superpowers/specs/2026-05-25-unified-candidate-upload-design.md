# Единая страница загрузки кандидатов

**Дата:** 2026-05-25
**Статус:** Дизайн утверждён, готов к планированию

## Проблема

Сейчас загрузка кандидатов разнесена на две страницы:

- `/candidates/upload` — одиночная загрузка. Умеет файл резюме **и** ссылку
  на портфолио (оба поля опциональны, можно передать вместе).
- `/candidates/upload/bulk` — пакетная загрузка. Умеет **только** ссылки на
  портфолио, без файлов.

Две страницы дублируют логику и сбивают с толку: чтобы загрузить пачку с
резюме-файлами, рекрутеру приходится грузить их по одному через одиночную
страницу. Хочется одно место, где можно добавить сколько угодно кандидатов,
и у каждого — и файл, и ссылка.

## Решение

Объединить обе страницы в одну по адресу `/candidates/upload`. Это
список карточек: одна карточка = один кандидат, в каждой и файловый
пикер, и поле для ссылки на портфолио. По умолчанию одна карточка; кнопка
«Добавить ещё кандидата» добавляет следующую.

Бэкенд не меняется — существующий `POST /api/candidates/upload` уже
принимает `resume` (файл) и `portfolioLink` (строку) в одном
multipart-запросе. Вся оркестрация остаётся клиентской, как в текущем
пакетном режиме.

### Архитектура: расширение существующего пакетного флоу

Текущий хук `useBulkUpload` уже умеет последовательную очередь, разбор
`201`/`409`, очередь на ревью и прерывание по «Стоп». Расширяем его
поддержкой файла на строку — это меньше работы и меньше риска, чем писать
новый оркестратор.

## Навигация

- `/candidates/upload` — единственная страница загрузки (заменяет обе).
- `/candidates/upload/bulk` → постоянный redirect на `/candidates/upload`
  (на случай старых ссылок/закладок).
- Быстрое действие «Загрузить пачкой» на главной (`/`) и ссылка
  «Загрузить пачкой» в шапке одиночной страницы больше не нужны как
  отдельные пункты — на главной остаётся одно действие «Загрузить
  кандидатов» → `/candidates/upload`.

## Поток работы

### 1. Ввод — список карточек

- По умолчанию одна карточка «Кандидат 1».
- В каждой карточке сверху подпись-номер «Кандидат N».
- Внутри карточки два поля:
  - **Файловый пикер** — компактная зона с пунктирной рамкой, принимает
    `.pdf` и `.docx`, лимит 10 MB. Показывает имя и размер прикреплённого
    файла, крестик для сброса. Поддерживает клик (выбор файла); drag-and-drop
    **не входит** в объём (см. YAGNI).
  - **Поле ссылки** — текстовый input для ссылки на портфолио.
- Под карточками — кнопка **«+ Добавить ещё кандидата»**, добавляет
  следующую карточку с номером N+1.
- У каждой карточки (кроме случая, когда она единственная) — крестик `×`
  справа от номера для удаления. Нумерация ниже пересчитывается.
- Кнопка **«Обработать N кандидатов»** активна, когда есть хотя бы одна
  валидная карточка. Карточка валидна, если в ней есть файл **или** непустая
  валидная ссылка. Пустые карточки при запуске игнорируются.

### 2. Обработка — строго последовательная

- Браузер идёт по валидным карточкам по одной (один запрос за раз —
  Playwright и AI-квота тяжёлые).
- Каждая карточка — мини-машина состояний:
  `ожидает → обрабатывается → создан / needs-direction / duplicate / ошибка`.
  Статусы `needs-direction` и `duplicate` объединяются в UI ярлыком
  «на ревью».
- Сверху живой прогресс «Обрабатываем X из N» + кнопка **«Стоп»** в тулбаре
  (прерывает остаток очереди; уже запущенный запрос завершается).
  Непройденные карточки возвращаются в `ожидает`.

### 3. Ревью-очередь — инлайн в карточке

- Карточки со статусом «на ревью» показывают разрешение прямо внутри себя:
  - **needsDirection** → `DirectionPicker` (переиспользуемый компонент);
    выбор направления → повторный запрос с `direction=` → «создан».
  - **duplicate** → `DuplicateWarning`: «Открыть существующего» / «Создать
    всё равно» (`forceCreate=true`) / «Пропустить».
  - **error** → кнопка «Повторить» (повторный запрос по той же карточке).

### 4. Итог

- Шапка-сводка: «Создано N · на ревью M · ошибок K».
- Ссылка на список кандидатов.
- Карточки «создан» показывают имя кандидата ссылкой на его профиль; если
  анализ портфолио не запускался — подпись «без анализа портфолио».

## Данные и состояния

Новое состояние в БД не вводится — всё живёт в памяти страницы. Тип строки
расширяется полем `file`:

```ts
interface BulkRow {
  id: string;
  url: string;
  file?: File;           // НОВОЕ: прикреплённое резюме
  status: "idle" | "pending" | "processing" | "created" | "needs-direction" | "duplicate" | "skipped" | "error";
  candidate?: CandidateResult;
  duplicate?: DuplicateInfo;
  needsDirection?: NeedsDirectionInfo;
  error?: string;
  noPortfolioAnalysis?: boolean;
}
```

### Изменения в `useBulkUpload`

- `BulkRow` получает `file?: File`.
- Новые методы управления вводом: `setFile(id, file)` и `clearFile(id)`.
- `uploadOne(url, file, options)` — добавляет `resume` в FormData, если файл
  есть; `portfolioLink` — если ссылка непустая.
- `start()` перестаёт принимать `urlList: string[]`. Вместо этого работает с
  текущими строками: фильтрует невалидные (нет ни файла, ни ссылки), помечает
  валидные как `pending`, обрабатывает последовательно. URL-дедуп остаётся,
  но применяется только к строкам, где есть ссылка (две строки только с
  файлами не считаются дублями).
- Методы разрешения (`resolveDirection`, `resolveForceCreate`, `retryRow`)
  получают и `url`, и `file` строки, чтобы повторный запрос нёс оба поля.

## Компоненты

- `src/app/candidates/upload/page.tsx` — полная замена на новый UI
  (список карточек). Текущий drop-zone-UI одиночной загрузки удаляется.
- `src/app/candidates/upload/bulk/page.tsx` — заменяется на redirect
  (`redirect("/candidates/upload")` через Next.js).
- `useBulkUpload` (`use-bulk-upload.ts`) — переезжает из `bulk/` в
  `upload/` рядом со страницей (или остаётся на месте, импорт обновляется).
  Файл расширяется поддержкой `file`.
- `DirectionPicker`, `DuplicateWarning` — переиспользуются без изменений.
- `parsePortfolioLinks` — переиспользуется для дедупа/валидации ссылок.
- Карточка кандидата (`CardCandidateRow` / `BulkRowView`) — расширяется
  файловым пикером и логикой «файл и/или ссылка».

## Краевые случаи

- **Карточка только с файлом (без ссылки).** Валидна. Анализ портфолио не
  запускается (нет ссылки), кандидат создаётся по резюме. URL-дедуп к ней
  не применяется.
- **Карточка только со ссылкой (без файла).** Как сейчас в пакетном режиме.
- **Карточка с файлом и ссылкой.** Оба поля уходят в один запрос — как в
  текущей одиночной загрузке.
- **Файл неверного типа/размера.** Отклоняется на выборе (как сейчас в
  одиночной странице): сообщение об ошибке под пикером, файл не
  прикрепляется.
- **Дубль-ссылка внутри пачки** → отсеивается на запуске
  (`parsePortfolioLinks`). Дубли по файлам не детектируются (нет дешёвого
  способа).
- **«Создан» ≠ анализ портфолио прошёл.** Как и в текущем пакетном режиме:
  если скрейпинг не дал скриншотов или ссылки не было, оценки портфолио =
  null. Помечаем подписью «без анализа портфолио».
- **Уход со страницы во время обработки** → предупреждение через
  `beforeunload` (известное ограничение SPA-навигации сохраняется).
- **Прерывание по «Стоп»** → непройденные карточки возвращаются в `ожидает`,
  обработку можно запустить повторно.

## Тестирование

- **Юнит-тест** на расширенную логику валидности строки (валидна, если файл
  **или** ссылка) — если она выносится в чистый хелпер. `parsePortfolioLinks`
  уже покрыт.
- **Ручная проверка** на запущенном приложении:
  - одна карточка только с файлом → создан;
  - одна карточка только со ссылкой → создан;
  - карточка с файлом + ссылкой → создан с анализом портфолио;
  - пачка из 3 (разные комбинации) → последовательная обработка, прогресс;
  - попадание в очередь по направлению и по дубликату → инлайн-разрешение;
  - «Стоп» во время обработки → возврат в «ожидает»;
  - `/candidates/upload/bulk` → redirect на `/candidates/upload`.
  E2E-харнесса в проекте нет.

## Что НЕ входит (YAGNI)

- Drag-and-drop в карточках (текущий одиночный drop-zone удаляется ради
  компактности списка). Можно вернуть позже, если будет нужно.
- Несколько файлов на одного кандидата.
- Фоновая очередь / персистентный job-state — масштаб 5–20 не требует.
- Параллельная обработка (конкурентность > 1) — последовательность безопаснее
  для Playwright и AI-квоты.
