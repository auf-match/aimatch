# Импорт базы дизайнеров из Behance-JSON + порционный AI-анализ — дизайн

**Версия:** 2026-07-03
**Статус:** утверждён к реализации

## Цель

Залить ~2000 профилей дизайнеров из выгрузки Behance (JSON) в базу одним действием, без AI и без затрат. Карточка на этом этапе — имя + ссылка на портфолио (+ то, что достаётся из JSON бесплатно). Полноценный AI-анализ (роль, грейд, навыки, оценки портфолио, эмбеддинг) запускается позже порциями, когда пользователь готов тратить время и деньги.

## Контекст

JSON — выгрузка профилей Behance. В каждой записи: `display_name`, `first_name`/`last_name`, `url` (профиль Behance), `location`/`city`/`country`, `occupation` (грязная строка), `fields` (категории Behance), `website` (иногда telegram/инстаграм/личный сайт, иногда пусто), `company` (иногда содержит email), `stats` (followers/appreciations/views), `images`.

**Чего в JSON нет:** резюме, грейда, опыта в годах, навыков. Всё это может дать только AI-анализ портфолио.

Проверено на реальных данных: существующий скрейпер **успешно** обрабатывает Behance-профиль (18k символов + 18 скриншотов). Но на удалённом профиле Behance отдаёт страницу «Не удалось найти эту страницу», и скрейпер **не отличает её от рабочей** — молотит 15k символов мусора. На 2000 профилей это сожжёт заметную часть AI-бюджета впустую.

## Ключевые решения

- **Импорт без AI.** Заливаем всех, кого нашли в файле. Секунды, $0.
- **Грейд и роль не угадываем.** В схеме `role: CandidateRole` и `grade: Grade` обязательные → ставим заглушки `role: OTHER`, `grade: MIDDLE`. Их заменит AI-анализ.
- **Следствие, принятое осознанно:** импортированные не участвуют в матчинге, пока не проанализированы — хард-фильтр отбирает по `role: vacancy.role`, а у них `OTHER`. Они «спящие», но в базе.
- **Заливаем всех**, без фильтрации по `fields`/`occupation` (в выборке есть графические дизайнеры и артисты — разберёмся позже через триаж/анализ).
- **Дедуп по ссылке на портфолио.** Behance-URL уникален; повторный импорт того же файла не задублирует.
- **Порционный анализ по кнопке.** Пользователь сам выбирает темп и расход.
- **Отсечка мёртвых профилей до AI.** Детектор 404-страницы Behance экономит бюджет.

## Архитектура

### Схема (Prisma)

Одно изменение — новый статус в существующий enum:

```prisma
enum CandidateStatus {
  NEW
  PARSED
  PORTFOLIO_ANALYZED
  ANALYSIS_FAILED   // ← новый: анализ не удался (мёртвый профиль/ошибка AI)
  ACTIVE
  IN_PROCESS
  ARCHIVED
}
```

Зачем: без него неудачный кандидат остаётся `NEW` и будет попадать в каждую следующую пачку, снова и снова жгя бюджет. Аддитивная миграция.

Статусы в этой фиче:
- `NEW` — импортирован, не анализирован (очередь).
- `PORTFOLIO_ANALYZED` — анализ прошёл (ставит существующая логика).
- `ANALYSIS_FAILED` — анализ не удался; в пачки больше не попадает, можно повторить точечно.

### Чистая логика (Vitest)

`src/lib/behance-import.ts`:
- `extractBehanceProfiles(json: unknown): BehanceProfile[]` — рекурсивно обходит произвольную вложенность JSON и собирает объекты, у которых есть `url`, содержащий `behance.net`, и непустое имя (`display_name` или `first_name`/`last_name`). Так парсер устойчив к обёрткам вокруг массива.
- `mapProfileToCandidate(p: BehanceProfile): CandidateImportRow` — маппинг (см. ниже).
- `isDeadBehancePage(title: string): boolean` — детектор мёртвой страницы по заголовку (`«Не удалось найти эту страницу»`, `«page not found»`, регистронезависимо).

Маппинг:

| JSON | → Candidate |
|---|---|
| `display_name`, иначе `first_name + last_name` | `name` (обязательное; запись без имени пропускается) |
| `url` | `portfolioLinks: [url]` |
| `website`, если это НЕ t.me | добавляется вторым элементом в `portfolioLinks` |
| `location` (иначе `city, country`) | `location` |
| `website`, если начинается с `t.me/` или `https://t.me/` | `telegramContact` |
| `company`, если похоже на email (`содержит @` и точку) | `email` |
| `occupation`, `fields`, `stats` | склеиваются в `aiSummary` как сырая заметка — чтобы не потерять контекст и дать AI подсказку |
| — | `role: "OTHER"`, `grade: "MIDDLE"`, `status: "NEW"`, `source: "behance"` |

### Импорт

`POST /api/candidates/import-json` — принимает JSON-файл (multipart). Логика:
1. Распарсить файл, `extractBehanceProfiles`.
2. Смаппить, отбросить записи без имени или без валидного URL.
3. Дедуп внутри файла по URL.
4. Дедуп против базы: выбрать существующих кандидатов, у которых `portfolioLinks` пересекается с URL из файла (`hasSome`), исключить их.
5. `createMany` пачкой (`skipDuplicates: true`).
6. Вернуть `{ found, imported, skippedExisting, skippedInvalid }`.

Размер файла: 2000 профилей — единицы МБ, проходит по лимиту (`middlewareClientMaxBodySize: 210mb` уже поднят).

### Порционный AI-анализ

`POST /api/candidates/analyze-batch` — body `{ limit: number }` (10/20/50):
1. Берёт `limit` кандидатов со `status: NEW`, у которых есть `portfolioLinks`.
2. Fire-and-forget обработка с параллелизмом **3** (щадящий режим для Behance и AI-квот).
3. Для каждого — переиспользуется существующая логика анализа портфолио (та же, что в `POST /api/candidates/[id]/reanalyze-portfolio`: `scrapePortfolio` → `analyzePortfolio`/`analyzePortfolioComm` → `prisma.candidate.update` со `status: PORTFOLIO_ANALYZED` + генерация эмбеддинга). Чтобы не дублировать код, эта логика выносится в сервис `src/server/services/candidate-analysis.ts` (функция `analyzeCandidatePortfolio(candidateId)`), и роут `reanalyze-portfolio` тоже начинает её использовать.
4. **Перед отправкой в AI:** если `isDeadBehancePage(scrapeResult.title)` → `status: ANALYSIS_FAILED`, AI не вызывается.
5. Любая ошибка (скрейп/AI) → `status: ANALYSIS_FAILED`.

`GET /api/candidates/analyze-batch/status` — возвращает `{ pending: number, failed: number }` (счётчики по статусам) для отображения прогресса и кнопки.

## UI

### Импорт — на `/candidates/upload`

Новый блок «Импорт из JSON» рядом с существующей ручной загрузкой:
- File picker (`accept=".json"`), кнопка «Загрузить файл».
- После выбора — превью результата парсинга на клиенте: «Найдено N профилей».
- Кнопка «Импортировать» → `POST /api/candidates/import-json` → результат: «Импортировано M, пропущено (уже в базе) K, без имени/ссылки L».
- Ошибка парсинга («не похоже на выгрузку Behance») — inline-сообщение.

### Порционный анализ — на `/candidates`

В шапке страницы, только если `pending > 0`:
- Текст «N кандидатов без AI-анализа».
- Кнопка «Проанализировать» + селект количества (10 / 20 / 50).
- Во время работы — кнопка дизейблится, показывается прогресс («Осталось N»); клиент поллит `GET .../status` каждые 5с, пока `pending` уменьшается.
- Если `failed > 0` — рядом приглушённо «M с ошибкой анализа» (информативно; повтор — точечно из карточки кандидата существующей кнопкой).

## Пограничные случаи

- **JSON не того формата** → `extractBehanceProfiles` вернёт пусто → 400 «Не найдено профилей Behance в файле».
- **Битый JSON** → 400 «Не удалось разобрать файл».
- **Запись без имени или без behance-url** → пропускается, считается в `skippedInvalid`.
- **Кандидат уже в базе** (по URL портфолио) → пропускается, считается в `skippedExisting`. Существующая карточка НЕ перезаписывается.
- **Мёртвый профиль Behance** → `ANALYSIS_FAILED` без вызова AI.
- **Behance забанил/таймаут** → `ANALYSIS_FAILED`, можно повторить позже.
- **Кандидат без `portfolioLinks`** → в пачку анализа не берётся (анализировать нечего).
- **Параллельные нажатия «Проанализировать»** → возможен захват пересекающихся наборов; на v1 не защищаем транзакционно, кнопка дизейблится на время запроса (внутренний инструмент, один пользователь).

## Что не делаем (YAGNI)

- Фильтрацию по `fields`/`occupation` при импорте.
- Угадывание роли/грейда эвристикой из `occupation`.
- Обновление существующих карточек при повторном импорте (только пропуск).
- Автоматический запуск анализа после импорта.
- Отдельную таблицу очереди — очередь выражается статусом `NEW`.
- Скачивание аватарок (`images`) и баннеров.
- Массовый повтор всех `ANALYSIS_FAILED` (повтор точечный из карточки).
