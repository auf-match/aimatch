# Drag-and-drop перемещение по этапам воронки — дизайн

**Версия:** 2026-07-03
**Статус:** утверждён к реализации

## Цель

Дать возможность перемещать кандидатов по этапам воронки перетаскиванием (drag-and-drop) на обеих досках — на странице вакансии (`pipeline-board.tsx`) и на общей странице «Этапы» (`all-pipelines-board.tsx`). Существующее меню перемещения по клику сохраняется.

## Ключевые решения

- **Библиотека:** `@dnd-kit/core`. `@dnd-kit/sortable` НЕ нужен — порядок внутри колонки не важен, только переброс между колонками.
- **Обе доски** получают drag. Единый UX.
- **Клик и drag сосуществуют.** `PointerSensor` с `activationConstraint: { distance: 8 }`: сдвиг < 8px = клик (открывает меню как сейчас), ≥ 8px = drag. Меню остаётся для «Открыть карточку кандидата / вакансию» и как альтернативный способ перемещения.
- **Переиспользование move-логики.** `handleMove(row, targetStage)` (оптимистичное обновление + revert рефетчем) уже есть в обоих компонентах; drag вызывает её же вместо меню.
- **DragOverlay** показывает «клон» карточки под курсором; исходная карточка приглушается (opacity) во время drag.
- **Auto-scroll** доски при перетаскивании к краю (встроено в `@dnd-kit`, включаем).

## Архитектура

### Зависимость

`npm install @dnd-kit/core` (React 19-совместима). Одна библиотека, ~10kb.

### Идентификаторы drag

- **Доска вакансии** (`pipeline-board.tsx`): draggable id карточки = `candidateId` (в рамках одной вакансии уникален).
- **Общая доска** (`all-pipelines-board.tsx`): draggable id = `${candidateId}::${vacancyId}` (кандидат может встречаться по нескольким вакансиям).
- **Droppable id колонки** (обе доски) = имя `PipelineStage` (значение enum, например `"DL_APPROVED"`).

При `onDragEnd` по droppable-id (этапу) и draggable-id находим соответствующую `PipelineRow` в state и вызываем `handleMove(row, targetStage)`.

### Структура компонентов (обе доски)

- Ряд колонок оборачивается в `<DndContext sensors={sensors} onDragStart={...} onDragEnd={...} autoScroll>`.
- Колонка (`BoardColumn`) — обёрнута `useDroppable({ id: stage })`. Подсветка колонки при `isOver` (лёгкий фон/бордер).
- Карточка (`CandidateCard`) — обёрнута `useDraggable({ id: cardId })`. Клик-onClick (открытие меню) сохраняется; drag активируется только после порога 8px, поэтому клик не конфликтует.
- `onDragStart` сохраняет id активной карточки в state (для `DragOverlay` и приглушения оригинала).
- `<DragOverlay>` рендерит визуальный клон карточки во время перетаскивания.

### Логика `onDragEnd`

```
onDragEnd(event):
  activeId = event.active.id
  overId = event.over?.id   // имя этапа или undefined
  сбросить activeId в state
  если overId нет → no-op (брошено мимо доски)
  найти row по activeId
  если row.stage === overId → no-op (та же колонка)
  иначе handleMove(row, overId as PipelineStage)
```

`handleMove` уже реализован в обоих компонентах и не меняется по сути (оптимистичное обновление + POST на move-эндпойнт + revert рефетчем при ошибке).

### Дублирование drag-обвязки

`CandidateCard`, `BoardColumn` и move-логика сейчас продублированы в двух файлах (общая доска дополнительно показывает вакансию на карточке). Drag добавляет `useDraggable`/`useDroppable`-обвязку. Чтобы не плодить копии, **выносим общий низкоуровневый wrapper** в отдельный модуль:

- `src/app/pipeline/board-dnd.tsx` (или `src/components/pipeline/`): экспортирует `DraggableCardWrapper` (обёртка с `useDraggable`, прокидывает listeners/attributes/setNodeRef и `isDragging`) и `DroppableColumnWrapper` (обёртка с `useDroppable`, прокидывает `setNodeRef` и `isOver`). Плюс общий хелпер `usePipelineSensors()` (PointerSensor + activationConstraint).

Специфику отрисовки карточки (что показывать — с вакансией или без) каждый board оставляет у себя, оборачивая свой JSX в эти wrapper'ы. Так drag-механика едина, а визуал остаётся раздельным. Если по ходу выяснится, что визуал карточек почти идентичен, допустимо свести карточку в один общий компонент с опциональным показом вакансии — но это не обязательно для v1.

## Пограничные случаи

- **Брошено мимо доски** (`over === null`) → no-op.
- **Брошено на ту же колонку** → no-op, API не дёргаем.
- **Терминальные этапы** (`REJECTED`, `HIRED`) — карточки перетаскиваются как обычные (можно вернуть из отказа/переместить нанятого).
- **Ошибка move** → существующий revert (рефетч) откатывает оптимистичное обновление; на общей доске рефетч уважает текущий фильтр (querystring).
- **Горизонтальный скролл + drag к краю** → auto-scroll включён.
- **Тач-устройства** — `@dnd-kit` поддерживает через pointer events; приоритет desktop, отдельной оптимизации под мобильный не делаем.
- **Клик по карточке** (открыть меню) — работает благодаря порогу активации 8px; быстрый клик не стартует drag.

## Тестирование

Drag — интеграционное UI-поведение, юнит-тестами не покрывается (существующая move-логика уже покрыта косвенно предыдущими фичами). Проверка вручную через dev-сервер:
1. На доске вакансии перетащить карточку в другую колонку → этап меняется, сохраняется после перезагрузки.
2. То же на общей доске «Этапы».
3. Клик по карточке по-прежнему открывает меню (порог 8px работает).
4. Бросок на ту же колонку / мимо доски — ничего не происходит.
5. Ошибка сети при move — карточка возвращается на место.

## Что не делаем (YAGNI)

- `@dnd-kit/sortable` и сортировку внутри колонки (порядок не важен).
- Отдельную мобильную/тач-оптимизацию сверх встроенной в `@dnd-kit`.
- Мультивыбор и перетаскивание нескольких карточек разом.
- Анимации reorder внутри колонки.
- Удаление меню перемещения по клику (оно остаётся).
