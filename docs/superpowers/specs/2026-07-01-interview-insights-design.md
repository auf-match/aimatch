# Инсайты с интервью — дизайн

**Версия:** 2026-07-01 (v2)
**Статус:** утверждён к реализации

## Цель

После встреч дизайн-лида с кандидатами — сохранить записи, автоматически извлечь оттуда практические инсайты для рекрутёра: на что лид обращает внимание, какие вопросы задаёт, что советовать кандидатам, что уточнять на прескрининге. С каждой новой записью инсайты **накапливаются** (не перезаписываются), пользователь может помечать важные и скрывать нерелевантные.

## Ключевые решения

- **Несколько записей на вакансию.** Каждая — отдельная строка в `VacancyInterview` (append-only).
- **Инсайты накапливаются, не перезаписываются.** Каждая новая запись обрабатывается независимо, AI-предложения мержатся в существующий пул с дедупликацией. Ручные правки, флаги `important`/`hidden` сохраняются.
- **Каждый инсайт — объект**, не строка. У него есть `id`, `text`, `important`, `hidden`, `origin`, `sourceInterviewId`.
- **Автогенерация после каждой READY-записи.** Без confirm — терять нечего.
- **Ручное редактирование чипов** остаётся: поменять текст, поставить/снять «важное», скрыть, добавить свой инсайт.
- **4 фиксированных категории.**
- **Ввод — текст и/или аудио.** Аудио через существующий `briefing-audio.ts`.
- **Fire-and-forget обработка + поллинг.** Как в «Уточнениях».

## Архитектура

### Модель данных (Prisma)

**Новая таблица `VacancyInterview`:**
```
VacancyInterview {
  id            String
  vacancyId     String  (FK → Vacancy, onDelete: Cascade)
  createdAt     DateTime
  actor         String
  source        VacancyInterviewSource   // TEXT | AUDIO
  rawText       String?                  // если TEXT — введённый текст
  audioFileUrl  String?                  // если AUDIO — путь к файлу
  transcript    String?                  // транскрипт аудио (после обработки)
  status        VacancyInterviewStatus   // PROCESSING | READY | FAILED
  errorMessage  String?
}

enum VacancyInterviewSource { TEXT AUDIO }
enum VacancyInterviewStatus { PROCESSING READY FAILED }
```

**На `Vacancy` добавляется одно поле:**
```
interviewInsights Json?
```

### Структура `interviewInsights`

```json
{
  "leadFocusAreas":         [Item, ...],
  "leadQuestions":          [Item, ...],
  "candidateTips":          [Item, ...],
  "prescreeningQuestions":  [Item, ...]
}
```

Тип `Item`:
```ts
{
  id: string,              // nanoid — стабильный, нужен для правок
  text: string,            // текст инсайта, редактируется
  important: boolean,      // «звёздочка»
  hidden: boolean,         // скрыт из основного вида
  origin: "ai" | "manual",
  sourceInterviewId?: string,  // id VacancyInterview (если origin=ai)
  createdAt: string        // ISO
}
```

Все 4 массива обязательно присутствуют (могут быть пустыми). Item в них уникальны по `id`.

### Поток обработки одной записи

1. Пользователь жмёт «+ Загрузить запись», отправляет форму (текст и/или аудио).
2. Backend создаёт `VacancyInterview(status=PROCESSING)`.
3. Если аудио — транскрибируем через `briefing-audio.ts`, сохраняем `transcript`. Статус → READY.
4. Запускаем анализ этого одного транскрипта: новый промпт `interview-insights-parse.ts` — на вход **транскрипт этой встречи** + короткий контекст вакансии (`title`, `role`, `grade`). На выход — 4 массива строк: сырые предложения от AI.
5. Мержим в `Vacancy.interviewInsights` (см. алгоритм ниже).

Fire-and-forget как в `VacancyUpdate`; клиент поллит `GET /interviews` каждые 3с пока есть PROCESSING.

### Алгоритм мержа

Для каждой из 4 категорий, для каждой строки от AI:
1. Нормализуем текст: `text.trim().toLowerCase()`.
2. Ищем в текущем `interviewInsights[category]` элемент, чей `text` при нормализации совпадает.
3. **Если найден** — пропускаем (дубликат). Существующий item не трогаем: сохраняем его `text` (как пользователь его переписал), флаги, id.
4. **Если не найден** — добавляем новый:
   ```ts
   {
     id: nanoid(),
     text: originalStringFromAI,   // без нормализации
     important: false,
     hidden: false,
     origin: "ai",
     sourceInterviewId: <VacancyInterview.id>,
     createdAt: now()
   }
   ```

Мерж выполняется в транзакции: `SELECT vacancy → merge in memory → UPDATE vacancy.interviewInsights`. При гонке двух параллельных обработок — оптимистичная блокировка через `updateMany` с check по `updatedAt` (или просто `$transaction([...])` с retry — на усмотрение, но реализовать хоть какую-то защиту от lost update).

### Чистая логика (Vitest)

Выносится в `src/lib/interview-insights.ts`, покрывается юнит-тестами:
- `mergeInsights(current: Insights, aiSuggestions: AiSuggestions, sourceInterviewId: string, now: Date): Insights` — реализует алгоритм выше, чистая функция.
- `sortInsightsForDisplay(items: Item[]): { visible: Item[], hidden: Item[] }` — важные наверх, потом по `createdAt` desc; разделяет по флагу `hidden`.
- `countInsightsForBadge(items: Item[]): { total, hidden, important }`.

## UI

### Секция «Инсайты с интервью»

Располагается на странице вакансии между «Уточнениями» и «Воронкой».

- **Заголовок** «Инсайты с интервью» + кнопка «+ Загрузить запись».
- **Timeline записей** — компактный, новые сверху. По каждой:
  - дата, актор, иконка (текст/аудио),
  - бейдж статуса: `PROCESSING` (спиннер) / `READY` (галочка) / `FAILED` (красный + «Повторить» → POST `.../retry`),
  - клик по записи раскрывает `transcript` под ней.
- **4 карточки категорий** (одна на массив):
  - Заголовок с иконкой + название на русском + счётчик «7 инсайтов, 2 скрыто, 3 важных».
  - Список видимых item'ов (`hidden === false`), отсортированный: `important` наверх → потом `createdAt` desc.
  - Каждая строка: `[★]` `[👁]` `текст (кликом — редактирование inline через textarea, blur сохраняет)` `[маленький бейдж AI/Ручной]`.
    - ★ — жёлтый когда `important=true`, серый когда нет. Клик — toggle.
    - 👁 — переключение `hidden`. При клике item уходит вниз в скрытую область.
  - Свёрнутый блок «Показать скрытые (N)» — при раскрытии показывает `hidden === true` item'ы приглушённо (opacity 0.6), с теми же контролами (чтобы можно было вернуть).
  - В самом низу — поле «+ Добавить свой инсайт» (input + Enter или кнопка).
- **Плейсхолдер:** если нет ни записей ни ручных инсайтов — вместо всего блока показать «Загрузите первую запись встречи с лидом» + большая кнопка «+ Загрузить запись».

### Форма загрузки

По образцу формы «Уточнений»:
- Textarea (плейсхолдер: «Кратко или полный транскрипт»).
- File picker `.m4a|.mp3|.aac` (валидация MIME/size как в brief).
- Кнопки «Отправить» / «Отменить».

## API

- `POST /api/vacancies/[id]/interviews` — multipart `{ rawText?, audio?, actor }` → создаёт `VacancyInterview(PROCESSING)`, запускает fire-and-forget обработку, возвращает запись.
- `GET /api/vacancies/[id]/interviews` — список всех записей (desc). Также возвращает актуальный `interviewInsights` (или отдельный `GET .../interview-insights`, но проще один эндпойнт, чтобы клиент не делал два запроса).
- `POST /api/vacancies/[id]/interviews/[interviewId]/retry` — перезапуск обработки упавшей записи (`FAILED → PROCESSING`, запускает `processVacancyInterview`).
- `PATCH /api/vacancies/[id]/interview-insights/items/[itemId]` — body `{ text?, important?, hidden? }` (все опциональные, replace-if-present). Правит одно поле.
- `POST /api/vacancies/[id]/interview-insights/items` — body `{ category, text }` → создаёт новый item с `origin: "manual"`, добавляет в соответствующий массив, возвращает.

`itemId` — стабильный (nanoid), клиенту приходит в GET и он им пользуется. Не завязано на индекс массива.

## Пограничные случаи

- **Аудио падает при транскрибации.** `VacancyInterview.status = FAILED` + `errorMessage`. Timeline показывает красную плашку + «Повторить». Инсайты не трогаются.
- **AI-анализ падает.** Запись остаётся READY (транскрипт есть), но новые item'ы не добавились. В UI рядом с записью — маленькая пометка «AI-анализ не удался» + «Повторить анализ» (тот же `.../retry` endpoint — понимает, откуда возобновлять: если `transcript` есть, идёт сразу к парсингу).
- **AI вернул кривой JSON.** Ошибка парсинга → те же FAILED в этой стадии → возможность повторить.
- **Пустой транскрипт.** `FAILED("Пустой транскрипт")`.
- **Гонка при параллельной обработке двух записей.** Мерж внутри транзакции + optimistic-lock (`updateMany` с check по `updatedAt`), при промахе — retry один раз.
- **Дубли от AI внутри одной записи.** Не проблема — на этапе мержа нормализуем и дедуплицируем.
- **Пользователь редактирует item, AI позже предлагает по сути то же.** Совпадение по нормализованному тексту → дубликат отсеян. Если пользователь сильно переписал — item будет считаться уникальным и появится второй; это ожидаемо, легко скрыть вручную.
- **Пользователь скрыл item, тот же текст AI предлагает снова.** Совпадение по нормализованному тексту с существующим (скрытым) item — не добавляем. Скрытый остаётся скрытым.
- **Удаление записи-интервью.** В v1 не даём (нет UI). Cascade delete только при удалении вакансии. Item'ы, которые пришли от удалённой записи, остались бы «сиротами» — но такой сценарий в v1 не наступает.

## Что не делаем (YAGNI)

- Полное удаление item'а (только hide). Полное удаление — v2.
- Удаление отдельной записи-интервью в UI.
- Экспорт советов в PDF / отправка кандидату.
- Реагрегация «пересчитать всё с нуля» — если сильно нужно, можно вручную через БД.
- Отслеживание «этот item пришёл из 3 разных интервью» — храним только первый `sourceInterviewId`.
- Права на просмотр важных vs обычных.
