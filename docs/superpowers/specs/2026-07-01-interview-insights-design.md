# Инсайты с интервью — дизайн

**Версия:** 2026-07-01
**Статус:** утверждён к реализации

## Цель

После первой встречи дизайн-лида с кандидатом (или нескольких встреч) — сохранить запись, автоматически извлечь оттуда практические инсайты для рекрутёра: на что лид обращает внимание, какие вопросы задаёт, что советовать кандидатам, что уточнять на прескрининге. При появлении новых записей — агрегировать общие инсайты по всем встречам с лидом.

## Ключевые решения

- **Несколько записей на вакансию.** Каждая — отдельная строка в `VacancyInterview` (append-only). Плюс агрегированные инсайты одним JSON на `Vacancy`.
- **AI работает по всем READY-записям сразу.** Не по одной — цель именно общие паттерны.
- **Ручное редактирование чипов.** Пользователь может добавлять/удалять/править элементы 4 списков; правки хранятся в `interviewInsights` вакансии.
- **Автогенерация только на первой загрузке.** Последующие — с confirm-диалогом «перезаписать ручные правки?». Отдельная кнопка «Пересчитать» — всегда доступна.
- **4 фиксированных категории** (`leadFocusAreas`, `leadQuestions`, `candidateTips`, `prescreeningQuestions`).
- **Ввод — текст и/или аудио.** Аудио прогоняется через существующий `briefing-audio.ts`.
- **Fire-and-forget обработка + поллинг.** Как в «Уточнениях».

## Архитектура

### Модель данных (Prisma)

**Новая таблица:**
```
VacancyInterview {
  id            String
  vacancyId     String  (FK → Vacancy, onDelete: Cascade)
  createdAt     DateTime
  actor         String
  source        VacancyInterviewSource   // TEXT | AUDIO
  rawText       String?                  // если TEXT — введённый текст
  audioFileUrl  String?                  // если AUDIO — путь к файлу
  transcript    String?                  // транскрипт аудио (после обработки)
  status        VacancyInterviewStatus   // PROCESSING | READY | FAILED
  errorMessage  String?
}

enum VacancyInterviewSource { TEXT AUDIO }
enum VacancyInterviewStatus { PROCESSING READY FAILED }
```

**На `Vacancy` добавляются:**
```
interviewInsights            Json?      // { leadFocusAreas, leadQuestions, candidateTips, prescreeningQuestions } — массивы строк
interviewInsightsGeneratedAt DateTime?  // когда AI генерировал; null = ещё не было автогенерации
```

`interviewInsights` — простой JSON:
```json
{
  "leadFocusAreas": ["строка", "..."],
  "leadQuestions": ["..."],
  "candidateTips": ["..."],
  "prescreeningQuestions": ["..."]
}
```

Все 4 массива обязательно присутствуют (могут быть пустыми).

### Поток обработки записи

1. Пользователь жмёт «+ Загрузить запись», заполняет форму (текст и/или аудио), отправляет.
2. Backend создаёт `VacancyInterview(status=PROCESSING)`.
3. Если аудио — транскрибируем через существующий `briefing-audio.ts`, сохраняем `transcript`.
4. Запись переходит в `status=READY`.
5. **Если это первая READY-запись у вакансии** (т.е. `interviewInsightsGeneratedAt` был null) — автоматически вызывается тот же самый код-путь, что и `/regenerate` (одна реализация, не две). Guard от гонки при параллельных загрузках: перед запуском делаем `prisma.vacancy.updateMany({ where: { id, interviewInsightsGeneratedAt: null }, data: { … } })` и запускаем только если обновилась 1 строка (иначе кто-то уже стартовал — no-op).
6. **Если не первая** — ничего дополнительно не делаем; в UI появляется кнопка «Пересчитать инсайты по всем N записям», нажатие которой требует confirm.

### Поток генерации инсайтов

`POST /api/vacancies/[id]/interview-insights/regenerate`:

1. Собираем все `VacancyInterview.transcript` для `status=READY` (по `createdAt` asc).
2. Склеиваем в один текст с разделителями `--- Запись от {date}, {actor} ---`.
3. Отдаём через новый промпт `interview-insights-parse.ts` — на вход склеенный текст + минимальный контекст вакансии (title, role, grade). На выход JSON с 4 массивами.
4. Записываем в `Vacancy.interviewInsights` (заменяя целиком) + `interviewInsightsGeneratedAt = now()`.

### Чистая логика (Vitest)

- `hasManualEdits(insights, lastGeneratedInsights): boolean` — сравнение текущего JSON с сохранённым снапшотом последней AI-генерации, чтобы определить нужен ли confirm-диалог. Опционально; в v1 можно упростить: просто всегда показывать confirm при N ≥ 2 (без хранения снапшота).

**В v1 идём по упрощённому пути:** confirm при любой загрузке кроме первой. Отдельного диффа не считаем.

## UI

### Секция «Инсайты с интервью»

Располагается на странице вакансии между секциями «Уточнения» и «Воронка».

- **Заголовок** + кнопка «+ Загрузить запись».
- **Список записей (timeline)** — компактный, новые сверху. По каждой: дата, актор, иконка (текст/аудио), бейдж статуса:
  - `PROCESSING` — серый спиннер «AI обрабатывает…».
  - `READY` — приглушённая галочка «Готова».
  - `FAILED` — красный «Ошибка: {errorMessage}» + кнопка «Повторить» → `POST .../retry`.
  Клик по записи раскрывает `transcript` (если есть) под ней.
- **Блок «Инсайты»** — под списком, 4 карточки (одна на категорию):
  - Заголовок категории (иконка + название на русском).
  - Чипы с текстом каждого элемента и кнопкой ✕ для удаления.
  - Инпут «+ добавить» внизу.
  - Изменения сохраняются на blur инпута через `PATCH /interview-insights` (без debounce — реже вызовов, проще).
- **Кнопка «Пересчитать инсайты по всем N записям»** — рядом с заголовком секции. Показывается только когда `≥1 READY-запись`. Клик:
  - Если N ≥ 2 или уже есть `interviewInsightsGeneratedAt` — confirm-диалог «Перезаписать текущие инсайты?». При ОК → POST `.../regenerate` → показываем спиннер → обновляем блок.
  - Если это первая генерация вообще — без confirm.

### Форма загрузки

По образцу формы «Уточнений»:
- Textarea для текста (плейсхолдер «Кратко о встрече или полный транскрипт»).
- File picker `.m4a|.mp3|.aac` (валидация как в brief).
- Кнопки «Отправить» / «Отменить».

### Плейсхолдер

Если ни одной записи и `interviewInsights` пусто — вместо блока инсайтов и timeline:
> «Загрузите первую запись встречи с лидом, чтобы AI выделил ключевые фокусы, вопросы и советы».

С кнопкой «+ Загрузить запись» посередине.

## API

- `POST /api/vacancies/[id]/interviews` — multipart `{ rawText?, audio?, actor }` → создаёт `VacancyInterview(PROCESSING)`, запускает fire-and-forget обработку, возвращает запись.
- `GET /api/vacancies/[id]/interviews` — список записей (desc).
- `POST /api/vacancies/[id]/interviews/[interviewId]/retry` — перезапуск обработки упавшей записи (`FAILED → PROCESSING`).
- `POST /api/vacancies/[id]/interview-insights/regenerate` — прогоняет все READY-записи, обновляет `interviewInsights` + `interviewInsightsGeneratedAt`.
- `PATCH /api/vacancies/[id]/interview-insights` — body `{ leadFocusAreas?, leadQuestions?, candidateTips?, prescreeningQuestions? }` — замена отдельных массивов целиком (для UI-редактирования чипов).

## Пограничные случаи

- **Аудио падает при транскрибации.** Запись переходит в `FAILED` с `errorMessage`. В timeline красная плашка + кнопка «Повторить». Инсайты не трогаются.
- **Regenerate падает.** Возвращаем 500, вакансию не трогаем. Пользователь видит toast/inline-error.
- **Первая запись прошла, автогенерация упала.** Запись остаётся READY, insights остаются пустыми, `interviewInsightsGeneratedAt` остаётся null. Пользователь видит кнопку «Пересчитать», может нажать ещё раз.
- **AI вернул кривой JSON.** Ловим ошибку парсинга → возвращаем 500 → пользователь видит «Не удалось разобрать ответ AI, попробуйте ещё раз».
- **Пустая запись после транскрибации.** Считаем ошибкой обработки → `FAILED("Пустой транскрипт")`.
- **Удаление отдельной записи.** В v1 не даём. Cascade delete происходит только при удалении вакансии целиком.
- **Ручное редактирование во время regenerate.** Regenerate перезапишет — это ожидаемое поведение (пользователь дал confirm).

## Что не делаем (YAGNI)

- Диф-превью «AI предлагает Х, применить?» — при агрегации перебор, проще целиком заменять с confirm.
- Пометки «этот совет из интервью №2» — общий пул.
- Удаление отдельных записей интервью (только через БД).
- Экспорт советов в PDF или отправка кандидату.
- Сравнение старых vs новых инсайтов при regenerate.
- Отдельные права на редактирование инсайтов.
