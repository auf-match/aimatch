# Общая воронка по всем вакансиям — дизайн

**Версия:** 2026-07-02
**Статус:** утверждён к реализации

## Цель

Дать дизайн-лиду единый обзор всех кандидатов в работе — доску-канбан по этапам, но сразу по всем открытым вакансиям, а не по одной. Отдельная страница «Этапы» в навигации. С доски можно перемещать кандидатов по этапам и фильтровать по вакансиям.

## Ключевые решения

- **Отдельная страница** `/pipeline`, пункт «Этапы» в сайдбаре после «Вакансии».
- **Карточка = пара кандидат×вакансия.** Один кандидат по двум вакансиям = две карточки. На карточке — имя кандидата + название вакансии/клиента.
- **Только открытые вакансии.** Записи `Pipeline` по вакансиям со статусом `OPEN` (закрытые/на паузе/черновики — не грузим, иначе шум).
- **Те же этапы 3–11**, что на доске вакансии (без «База»/«Новый»). Переиспользуем `PIPELINE_STAGE_ORDER` из `@/lib/pipeline`.
- **Фильтр по вакансиям** — мультиселект, по умолчанию все.
- **Перемещение прямо с доски** — то же меню, что на доске вакансии; `vacancyId` берётся из карточки.
- **Отдельный компонент доски** (`all-pipelines-board.tsx`), не переусложняем `pipeline-board.tsx`. Общая логика (`getPipelineActor`, лейблы/цвета этапов, `groupPipelineByStage`) уже в `@/lib/pipeline`.

## Архитектура

### API

Новый роут `GET /api/pipeline`:
- Query: `?vacancyIds=id1,id2` — опционально сузить набор вакансий. Формат: comma-separated. Отсутствует/пусто → все открытые. Неизвестные id просто не сматчат ничего (валидацию не делаем — лишние id безвредны).
- Логика: находит все `Pipeline`, где связанная `Vacancy.status === "OPEN"` **И** (если задан `vacancyIds`) `vacancyId ∈ list`. Это AND: явно запрошенная, но закрытая вакансия всё равно исключается (общая доска — только по открытым). Возвращает по каждой записи:
  ```
  {
    candidateId, candidate: { id, name, role, grade },
    vacancyId, vacancy: { id, title, clientName },
    stage, score (number|null), lastTransitionAt (ISO)
  }
  ```
- Score: `DetailedScore.overallScore` при наличии, иначе `MatchResult.overallScore`, иначе null (та же логика, что в `/api/vacancies/[id]/pipeline`).
- Плюс отдельный список открытых вакансий для фильтра можно получить из существующего `GET /api/vacancies` — отдельного эндпойнта не заводим.

Существующие эндпойнты переиспользуются как есть:
- `POST /api/vacancies/{vacancyId}/pipeline/{candidateId}/move` — перемещение (vacancyId из карточки).

### Данные для фильтра

Список вакансий для мультиселекта берём из `GET /api/vacancies` (уже возвращает `{ data, pagination }`), фильтруя на клиенте по `status === "OPEN"`.

### Группировка

Переиспользуем `groupPipelineByStage(rows)` из `@/lib/pipeline` — она группирует по `stage` в каноническом порядке. Новой чистой логики не добавляется, поэтому новых unit-тестов нет (существующие покрывают группировку).

## UI

### Страница `/pipeline`

- **Заголовок** «Этапы» (или «Воронка по всем вакансиям»).
- **Панель над доской:**
  - Мультиселект-фильтр «Вакансия: все ▾» (открытые вакансии; выбор сужает набор). При выборе подмножества — `?vacancyIds=` в запросе.
  - Счётчик «N кандидатов в воронке» (по текущему отфильтрованному набору).
- **Доска** — горизонтально скроллящийся ряд из 9 колонок (этапы 3–11: `PIPELINE_STAGE_ORDER`). Заголовок колонки: цветная точка (`PIPELINE_STAGE_COLORS`), лейбл (`PIPELINE_STAGE_LABELS`), счётчик.
- **Карточка** (кандидат×вакансия):
  - Имя кандидата, роль (`ROLE_LABELS`) + грейд (`GRADE_LABELS`).
  - Строкой ниже — название вакансии + клиент (приглушённо).
  - Score как `{score}%` (цвет по диапазону), дни в этапе через `daysInStage(new Date(lastTransitionAt), new Date())`.
  - Терминальный этап `REJECTED` — приглушённая карточка (opacity).

### Меню перемещения

Клик по карточке → попап (опаковый `bg-white dark:bg-zinc-900`, конвенция проекта):
- Список этапов из `PIPELINE_STAGE_ORDER` **без текущего** (фильтруем текущий этап карточки). Выбор → resolve актора (`getPipelineActor()`) → `POST /api/vacancies/{vacancyId}/pipeline/{candidateId}/move` → оптимистично обновить строку в state.
- Разделитель, затем:
  - «Открыть карточку кандидата» → `/candidates/{candidateId}` (SPA-навигация `useRouter().push`).
  - «Открыть вакансию» → `/vacancies/{vacancyId}`.

### Поллинг / обновление

Одноразовая загрузка на маунт + refetch при смене фильтра. Без авто-поллинга (в отличие от аудио-обработки — здесь фоновых операций нет). После перемещения — оптимистичное обновление state.

### Пустые состояния

- Нет ни одной записи (по текущему фильтру) → центрированный текст «Пока никто не в воронке».
- Пустая колонка → «—».

### Сайдбар

В `src/components/sidebar.tsx` в массив `nav` добавить пункт `{ href: "/pipeline", label: "Этапы", icon: <подходящая иконка, напр. columns/kanban из lucide> }` после «Вакансии».

## Пограничные случаи

- **Кандидат в воронке по закрытой вакансии.** Не показываем (фильтр по `status: OPEN`). Если вакансию закрыли — карточки уходят с общей доски (но остаются на странице самой вакансии).
- **Много карточек в колонке.** Колонка скроллится вертикально (как на доске вакансии); ряд колонок — горизонтально.
- **Перемещение упало (404/500).** Показать краткую inline-ошибку / откатить оптимистичное обновление рефетчем, как в `pipeline-board.tsx`.
- **Фильтр выбрал вакансии, которых нет записей** — доска с пустыми колонками + «—».
- **Гонок нет** — перемещение через существующий транзакционный эндпойнт.

## Что не делаем (YAGNI)

- Drag-and-drop (перемещение только через меню, как везде в проекте).
- Авто-поллинг.
- Сохранение выбранного фильтра между сессиями.
- Массовые действия (выбрать несколько карточек и переместить).
- Показ этапов «База»/«Новый» на общей доске.
- Группировка/своды по вакансиям внутри колонки — просто плоский список карточек.
