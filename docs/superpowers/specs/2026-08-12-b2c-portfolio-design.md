# B2C-часть: публичный разбор портфолио

Дата: 12 августа 2026

## Что делаем

Открытая страница, где дизайнер оставляет ссылку на портфолио и получает
разбор. Заявка сохраняется отдельно от рабочей базы кандидатов; дизайн-лид
просматривает накопившееся и переносит нужных в основную базу вручную.

Доступа к остальному продукту у дизайнера нет — он видит только свой разбор.

## Границы

Внутри: публичная форма, обработка заявки, страница результата, отдельное
хранилище, экран переноса, изоляция прав в базе.

Снаружи: уведомления в телеграм и на почту, персональная ссылка на результат,
ограничение частоты запросов, оплата. Каждое из этого решено не делать
осознанно — см. «Осознанно не делаем».

## Модель данных

Заявки живут в собственной таблице. В таблицу кандидатов публичный путь
не пишет никогда — ни строчки кода для этого не существует.

```prisma
model PortfolioSubmission {
  id        String   @id @default(cuid())
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  // Что прислал человек
  name         String
  contact      String
  portfolioUrl String
  // Нормализованная ссылка — по ней сверяем дубли при переносе
  dedupKey     String
  // Момент согласия на обработку данных: требование 152-ФЗ
  consentAt    DateTime

  // Обработка
  status       SubmissionStatus @default(PROCESSING)
  errorMessage String?
  startedAt    DateTime?
  finishedAt   DateTime?

  // Результат
  direction     String?  // продуктовый или коммуникационный дизайнер
  analysis      Json?    // полный разбор портфолио
  parsedProfile Json?    // роль, грейд, навыки — понадобится при переносе

  // Перенос
  transferredCandidateId String?
  transferredAt          DateTime?
  transferredBy          String?

  @@index([status, createdAt])
  @@index([dedupKey])
}

enum SubmissionStatus {
  PROCESSING
  READY
  FAILED
  TRANSFERRED
  DISMISSED
}
```

Почему отдельная таблица, а не флаг у кандидата: внешние заявки не могут
попасть в списки и в матчинг, потому что их там физически нет. Изоляция не
зависит от того, помнит ли каждый запрос про фильтр.

## Изоляция прав в базе

Отдельная таблица не защищает от взлома — это то же подключение и те же
права. Настоящая граница проводится ролью в Postgres.

- В Neon создаётся роль `auf_public` с правами **только** на
  `PortfolioSubmission`: `SELECT`, `INSERT`, `UPDATE`. Ни `DELETE`, ни любого
  доступа к `Candidate`, `Vacancy`, `MatchResult` и остальным таблицам.
- Строка подключения этой роли живёт в переменной `PUBLIC_DATABASE_URL`.
- Публичный путь ходит через отдельный клиент `prismaPublic`, привязанный к
  этой строке. Основной клиент в публичном коде не импортируется.
- Миграции по-прежнему накатываются основной ролью при старте контейнера.

Итог: успешная инъекция через публичную форму упирается в отсутствие прав.
До 2352 карточек кандидатов она не дотягивается.

Дополнительно и обязательно к соблюдению:

- В публичном пути нет `$queryRaw` и любого другого сырого SQL.
- Наружу отдаётся типизированный срез, а не запись целиком — приём тот же,
  что в портрете для агентства: чего нет в типе, то не утечёт, даже если
  завтра в таблицу добавят поле.

## Маршруты и доступ

Единственное место, где приложение открывается миру.

- `/p/portfolio` — форма и результат.
- `/api/p/submissions` — создание заявки.
- `/api/p/submissions/[id]` — статус и результат.

Список публичных адресов лежит в `src/lib/public-routes.ts` — уже написан,
покрыт девятью тестами, в том числе на ловушки: `/pipeline` начинается на
`/p`, но публичным не считается. Тот же модуль решает, рисовать ли сайдбар,
поэтому лейаут и авторизация не могут разъехаться.

Middleware получает исключение ровно по `isPublicRoute`. На это пишется
отдельный тест: публичная страница открывается без пароля, а `/candidates`,
`/api/vacancies` и прочее — по-прежнему с паролем.

## Поток обработки

1. Человек заполняет имя, контакт, ссылку и отмечает согласие.
2. `POST /api/p/submissions` проверяет поля, нормализует ссылку, создаёт
   запись со статусом `PROCESSING`, запускает обработку в фоне и возвращает id.
3. Страница опрашивает `GET /api/p/submissions/[id]` раз в несколько секунд.
4. Обработка: скрейпинг портфолио → классификация направления → разбор через
   Gemini. Результат кладётся в `analysis` и `parsedProfile`, статус `READY`.
5. Если не уложились в отведённое время или скрейпинг упал — статус `FAILED`
   с текстом причины.

### Разделение конвейера

Сейчас `analyzeImportedCandidate(candidateId)` читает кандидата, считает и сам
пишет результат в таблицу кандидатов — шесть мест записи. Для публичного пути
это не годится: он не должен уметь писать в `Candidate`.

Конвейер разделяется на две части:

- `analyzePortfolioAt(url, context)` — считает и **возвращает** результат,
  ничего не сохраняя.
- Сохранение остаётся на вызывающей стороне: внутренний путь пишет в
  `Candidate`, публичный — в `PortfolioSubmission`.

Существующий `analyzeImportedCandidate` переводится на ту же функцию, так что
логика анализа остаётся в одном экземпляре, а не копируется.

### Таймаут

У обработки жёсткий предел по времени. Он нужен не для красоты: скрейпер
умеет висеть часами на закрытых портфолио — это наблюдалось на живых ссылках
Behance. Без предела человек остался бы перед вечным индикатором загрузки.

## Что видит дизайнер

Порядок и состав блоков повторяют карточку кандидата, но без единой цифры:

1. Общее впечатление.
2. Разбор по критериям — те же семь шкал, только текстом. Для коммуникационных
   дизайнеров подставляется их набор критериев.
3. Сильные стороны и что усилить. Внутреннее слово «опасения» заменено на
   «что усилить»: внутри это заметка для дизайн-лида, снаружи — обратная связь
   человеку.
4. Разбор кейсов — раскрывающийся список.

Числовых оценок нет нигде. Причина не в мягкости: «метрики 38» читается как
приговор и приглашает спорить, а по числам видно, что подкрутить в портфолио,
чтобы пройти отбор.

## Перенос в основную базу

Внутренняя страница за паролем, список готовых заявок.

По каждой видно: имя, контакт, ссылку, направление, дату и полный разбор.
Рядом — результат сверки по `dedupKey`: если такое портфолио в базе уже есть,
заявка помечается «уже есть» со ссылкой на существующую карточку.

Действия: перенести (по одной или пачкой) и отклонить.

Перенос создаёт карточку кандидата с `source = "Публичная форма"`, переносит
разбор и распознанный профиль, ставит статус `PORTFOLIO_ANALYZED` и триаж
`NEW`. В заявке проставляются `transferredCandidateId`, `transferredAt` и
`transferredBy`, статус меняется на `TRANSFERRED`.

Повторный перенос той же заявки невозможен — статус уже не `READY`.

## Осознанно не делаем

**Ограничение частоты запросов.** Решено запускаться без него и посмотреть на
реальный трафик. Риск назван прямо: один скрипт в цикле за ночь нагенерирует
счёт за Gemini и забьёт таблицу заявок. Код пишется так, чтобы ограничение
добавлялось одной функцией в месте создания заявки.

**Аварийный выключатель — предлагается добавить.** Переменная окружения
`PUBLIC_FORM_ENABLED`: при `false` форма отдаёт «приём заявок временно
закрыт». Это не защита от накрутки, а способ закрыть кран за минуту, не
выкатывая новую сборку. Требует подтверждения.

**Персональная ссылка на результат.** Выбран вариант «ждать на странице»:
закрыл вкладку — потерял результат. Побочный эффект: id заявки всё равно нужен
для опроса статуса, поэтому он окажется в адресе, и случайная перезагрузка
результат не потеряет. Это не отдельная функция, а следствие устройства.

**Уведомления.** Требуют бота или почтового сервиса — отдельная интеграция.

## Риски

**Ошибка в исключении middleware откроет наружу лишнее.** Самое опасное место
во всей затее. Защита: список публичных адресов в одном модуле под тестами,
плюс тест на то, что внутренние маршруты остаются под паролем.

**Публичный клиент случайно получит доступ к основным таблицам.** Например,
кто-то импортирует основной `prisma` в публичный роут. Защита: права роли в
базе — такой запрос упадёт с ошибкой прав, а не тихо отработает.

**Скрейпер зависает на части портфолио.** Часть людей увидит экран ошибки
вместо разбора. Экран объясняет вероятные причины: сайт под паролем, требует
входа, слишком долго отвечает.

**Качество разбора выйдет наружу.** Внутри неточная формулировка — рабочий
момент, снаружи это лицо агентства. Перед открытием ссылки стоит прогнать
десяток реальных портфолио и прочитать, что получилось.

## Порядок работ

1. Таблица и миграция.
2. Роль в Postgres, `PUBLIC_DATABASE_URL`, отдельный клиент.
3. Разделение конвейера анализа на «посчитать» и «сохранить».
4. Публичные роуты создания и статуса.
5. Исключение в middleware плюс тесты.
6. Страница `/p/portfolio` на основе готового прототипа.
7. Внутренняя страница переноса со сверкой дублей.
8. Прогон на реальных портфолио до открытия ссылки.
