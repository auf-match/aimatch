# Импорт из выгрузки Huntflow — дизайн

**Версия:** 2026-07-20
**Статус:** утверждён к реализации

## Проблема

Существующий импорт (`docs/superpowers/specs/2026-07-03-behance-import-design.md`) написан под выгрузку профилей Behance. Реальная база агентства — экспорт из Huntflow (ATS), формат совершенно другой.

Загрузка реального файла (`applicants.json`, 94 МБ, 3934 записи) дала:

```
Импортировано 144. Пропущено: уже в базе 2, без имени/ссылки 0. Всего найдено 146.
```

`невалидных 0` при `найдено 146` означает, что узкое место — **извлечение**, а не маппинг: `extractBehanceProfiles` считает профилем только объект, у которого в поле `url` лежит `behance.net`. В Huntflow-записи такого поля нет.

### Что реально в файле

| Метрика | Значение |
|---|---|
| Всего applicant'ов | 3934 |
| С именем | 3922 |
| С текстом резюме (`externals[].data.body`) | 3589 (медиана 239 симв.) |
| **С ≥1 ссылкой на портфолио (прототип классификатора)** | **2100** |
| Импортируется сейчас | 144 |

Ссылки на портфолио лежат **внутри текста резюме** (`externals[].data.body`), вперемешку с инфраструктурным мусором: `api.hh.ru` (2012), `hhcdn.ru` (1399), `store.huntflow.ru` (1026), `hh.ru` (490) — около 80% всех URL в файле. Плюс `mir-s3-cdn-cf.behance.net` (431) — это CDN-картинки Behance, а не профили.

Портфолио-домены: behance 1087, figma 237, notion 116, dribbble 108, designer.ru 64, readymag 32, dprofile.ru, artstation, десятки `*.tilda.ws`, `*.super.site`, `*.framer.website`, `*.notion.site`.

## Принятые решения

1. **Импортируем только тех, у кого есть ссылка на портфолио** (~2100). Люди без портфолио не заводятся — база остаётся чистой, в выгрузке есть и не-дизайнеры (напр. front-end разработчики).
2. **AI-анализ не меняется** — как и сейчас, скрейпим портфолио-ссылку. Текст резюме из Huntflow для анализа не используем (медиана 239 символов — слишком мало, чтобы окупать усложнение пайплайна). Скрейпер на Playwright уже работает с любой платформой.
3. **Behance-путь сохраняем.** Роут импорта авто-детектит формат.

## Архитектура

### Новый модуль `src/lib/huntflow-import.ts`

Чистая логика без I/O, по образцу `src/lib/behance-import.ts`, покрыта Vitest.

**Экспорт:**
- `extractHuntflowApplicants(json: unknown): HuntflowApplicant[]` — берёт `json.items` (массив). Не рекурсивный обход: формат Huntflow плоский и предсказуемый, гадать не нужно.
- `mapApplicantToCandidate(a: HuntflowApplicant): CandidateImportRow | null` — `null`, если нет имени **или** нет ни одной портфолио-ссылки.
- `classifyUrls(urls: string[]): { portfolioLinks: string[]; telegram?: string; linkedin?: string }` — отдельная экспортируемая функция, ядро фичи, тестируется изолированно.
- `isHuntflowExport(json: unknown): boolean` — детектор формата для роута.

### Классификация ссылок

Из текста резюме (`externals[].data.body`, все `externals` склеиваются) регуляркой достаются все URL, затем:

**Allowlist портфолио-хостов** (точное совпадение хоста без `www.`, либо суффикс поддомена):

```
behance.net            dribbble.com          readymag.com
notion.so              *.notion.site         figma.com
designer.ru            dprofile.ru           coroflot.com
artstation.com         cargocollective.com   *.myportfolio.com
*.tilda.ws/.cc/.ru     *.super.site          *.framer.website/.ai/.app
*.webflow.io           *.github.io
```

**Важно:** сравнение по хосту, а не подстрокой. Это отсекает `mir-s3-cdn-cf.behance.net` (CDN-картинки), который иначе прошёл бы как «behance».

**Особые случаи:**
- `t.me` → `telegramContact` (не портфолио).
- `linkedin.com` и поддомены → `linkedinUrl`.
- Всё остальное (hh.ru, huntflow.ru, домены работодателей, соцсети) — игнорируется.

**Почему allowlist, а не «всё кроме мусора»:** в резюме много ссылок на работодателей и соцсети, перечислить их все в denylist невозможно. Allowlist известных платформ даёт 2100 чистых записей без ложных срабатываний. Редкий кастомный домен пропустим — это дешевле, чем натащить мусор в базу. Список вынесен в константу, расширяется одной строкой.

**Нормализация Behance:** ссылки вида `behance.net/username/moodboards` (вкладка профиля) режутся до `behance.net/username` — иначе скрейпер получит вкладку, а не портфолио. Исключение: `behance.net/gallery/...` — это отдельный проект, оставляем как есть (корень профиля из него не вывести).

**Дедуп и порядок:** дубликаты URL схлопываются, оставшиеся сортируются «лучшая первой»:

```
0. behance.net
1. dribbble.com
2. личные сайты (notion, tilda, super.site, framer, readymag, webflow, myportfolio, cargocollective, designer.ru, dprofile.ru)
3. figma.com
4. остальное
```

Анализ скрейпит `portfolioLinks[0]`, поэтому первой должна стоять самая содержательная ссылка. Figma ниже личных сайтов: это обычно один файл/прототип, а не портфолио целиком. У 422 человек ссылок несколько — сохраняем все.

### Маппинг полей

| Источник (Huntflow) | Поле кандидата |
|---|---|
| `first_name` + `last_name` (+ `middle_name`) | `name` |
| портфолио-ссылки из `externals[].data.body` | `portfolioLinks` (отсортированы) |
| `t.me`-ссылка из тела резюме | `telegramContact` |
| `linkedin.com`-ссылка из тела резюме | `linkedinUrl` |
| `email` (верхний уровень) | `email` |
| `externals[].data.area.name`, иначе `externals[].data.city` | `location` |
| `phone` (верхний уровень) | `phone` — **поля нет в схеме, не пишем** |
| — | `role: "OTHER"`, `grade: "MIDDLE"`, `status: "NEW"`, `source: "huntflow"` |

**Плейсхолдер Huntflow:** у части записей `email` = `office@huntflow.ru` (служебный адрес системы, не кандидата). Любой `@huntflow.ru` отбрасываем. Проверено на файле: таких 3 записи из 3934, реальных email — 1241. Случай редкий, но фильтр дешёвый.

**Локация:** проверено на файле — поля `externals[].data.area.title` **не существует**. Реальные источники: `externals[].data.area.name` (223 записи, напр. `"Санкт-Петербург"`) и `externals[].data.city` (110 записей, напр. `"Тюмень"`). Берём первое непустое из `area.name`, затем `city`; иначе `undefined`. Покрытие всего 8.4% (332 из 3934) — большинству локацию потом проставит AI-анализ по портфолио (`candidate-analysis.ts` мержит через `data.location ?? candidate.location`, импортированное значение не затирается).

**Телефон:** в модели `Candidate` поля `phone` нет. Не добавляем — вне scope, контакт есть через email/telegram.

### Изменения в существующем коде

1. **`src/app/api/candidates/import-json/route.ts`** — авто-детект: `isHuntflowExport(json)` → Huntflow-парсер, иначе существующий Behance-парсер. Ответ (`{found, imported, skippedExisting, skippedInvalid}`) и логика дедупа не меняются. Дедуп против базы по-прежнему сравнивает первую (основную) ссылку.

2. **`src/app/api/candidates/analyze-batch/route.ts` и `.../status/route.ts`** — фильтр `source: "behance"` заменяется на `source: { in: IMPORT_SOURCES }`, где `IMPORT_SOURCES = ["behance", "huntflow"]` — общая константа, чтобы выборка пачки и счётчики не разъехались. Смысл фильтра сохраняется: не захватывать кандидатов, заведённых обычной загрузкой.

3. **`src/app/candidates/upload/import-json-block.tsx`** — текст «Выгрузка профилей Behance» → нейтральный, упоминающий оба формата.

### Что НЕ меняется

- `src/server/services/candidate-analysis.ts` — анализ работает как есть, скрейпер платформо-независим.
- Схема БД — `source` уже строка, новых полей и статусов не нужно.
- `src/lib/behance-import.ts` — Behance-путь остаётся рабочим.
- Эмбеддинги, матчинг, UI порционного анализа.

## Пограничные случаи

- **Нет `externals`** — тела резюме нет, ссылок нет → пропуск (`skippedInvalid`).
- **Несколько `externals`** — тела склеиваются, ссылки собираются из всех.
- **Нет имени** → пропуск.
- **Только `figma.com`** → импортируем, figma станет основной ссылкой (лучше, чем ничего).
- **Человек уже импортирован Behance-путём** — дедуп против базы по основной ссылке отсекает, попадёт в `skippedExisting`.
- **Дубли внутри файла** — схлопываются по основной ссылке, как в Behance-пути.
- **Файл 94 МБ** — текущий роут (`JSON.parse(await file.text())`) уже успешно обработал этот файл целиком, лимиты не трогаем.
- **Битый URL** (не парсится `new URL`) — молча пропускается, не роняет запись.

## Тестирование

Vitest на `src/lib/huntflow-import.ts` — синтетическая Huntflow-запись (по образцу реальной), покрывает:
- извлечение `items`, детектор формата `isHuntflowExport`;
- имя из `first_name`/`last_name`, пропуск без имени;
- allowlist: behance/dribbble/notion.site/tilda проходят, `api.hh.ru`/`store.huntflow.ru`/`mir-s3-cdn-cf.behance.net` — нет;
- `t.me` → `telegramContact`, linkedin → `linkedinUrl`, не в `portfolioLinks`;
- нормализация `behance.net/user/moodboards` → `behance.net/user`, но `behance.net/gallery/...` не трогается;
- сортировка «лучшая первой», дедуп URL;
- отбрасывание `@huntflow.ru`;
- `null` без портфолио-ссылок.

Ручная проверка: пилот на реальном файле — ожидаем ~2100 импортированных (сейчас 144), затем порционный анализ на 10 записях и проверка, что кандидат проходит хард-фильтр матчинга.

## Что не делаем (YAGNI)

- Не используем текст резюме для AI-анализа (решение выше).
- Не добавляем поле `phone` в схему.
- Не обобщаем `isDeadBehancePage` на другие платформы — для не-Behance мёртвой страницы потратим один лишний AI-вызов, чинить преждевременно.
- Не парсим `externals[].data.experience` в `Experience` — опыт добирается AI-анализом.
- Не импортируем людей без портфолио-ссылки.
- Не трогаем логи/теги/вакансии/фото из Huntflow.
- Не делаем отдельный роут под Huntflow — авто-детект в существующем.
